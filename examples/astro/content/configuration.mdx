# Basic Configuration

`heyo-docs.config.ts` is the single source of truth for a Heyo Docs site.
The framework integration and the documentation UI read the same validated
object, so a change to navigation or metadata does not need to be repeated in
multiple places.

## Start with the site model

The generated project already includes a working configuration. Update the
identity fields first, then point `content` at the directory that contains
your MDX files.

<CodeBlock language="ts" title="heyo-docs.config.ts" showLineNumbers>
  {`import { heyoDocs } from "@heyo-sh/heyo-docs/config";

export default heyoDocs({
  title: "Heyo Docs example",
  description: "Guides and reference for Heyo Docs example.",
  content: "./content",
  theme: "grain",
  mode: "system",
  branding: { name: "Heyo Docs example" },
});`}
</CodeBlock>

Set `siteUrl` to the final public origin before publishing. It is used for
canonical URLs, social metadata, the sitemap, RSS, and AI-facing discovery
files.

## Organize the sidebar

Use `groups` to define the order readers see. A group contains named sections
and their MDX page references; a reference is relative to `content` and does
not include the `.mdx` extension.

<CodeBlock language="ts" title="heyo-docs.config.ts">
  {`groups: [
  {
    group: "Documentation",
    icon: "globe",
    sections: [
      {
        section: "Get Started",
        icon: "lightbulb",
        pages: ["quickstart", "configuration"],
      },
      {
        section: "Essentials",
        icon: "book",
        pages: ["essentials/text-styling", "essentials/code-blocks"],
      },
    ],
  },
],`}
</CodeBlock>

The order is meaningful: it controls the sidebar and the previous/next links at
the end of each article. Use a page object with `title` and `src` when a
sidebar entry should point to a page outside the local documentation.

## AI chat

Add `ai.chat` to enable a documentation-aware chat through [Pi](https://github.com/badlogic/pi-mono).
Use any provider identifier bundled with the installed Pi version, such as
`openai`, `anthropic`, `google`, `openrouter`, or `xai`. Authentication stays
server-only and is supplied by the route that handles the chat request.

<CodeBlock language="ts" title="heyo-docs.config.ts">
  {`ai: {
  chat: {
    provider: "openai",
    model: "gpt-5-mini",
    variant: "right", // "center" shows the compact prompt first
    icon: "chat",
    text: "AI Chat",
    name: "Docs Assistant", // name shown in the drawer and message labels
    placeholder: "Ask AI about the docs", // used in the compact prompt and drawer
  },
},`}
</CodeBlock>

`provider` and `model` are required. Keep the credential out of this
configuration and pass it as `auth` to `createAiChatResponse` in the server
route. Cloudflare routes obtain the key from the Worker `env` binding; Node.js
routes can read their server environment there. GitHub Copilot and OpenAI Codex
use `auth: { type: "oauth", getAccessToken }`; Amazon Bedrock uses either
`{ type: "aws", region?, profile? }` and the AWS credential chain, or
`{ type: "bedrock-bearer", token, region? }`. The model must be an actual model
identifier, not the provider name. Amazon Bedrock requires a Node.js chat
endpoint. `variant` defaults to `right`. `name`
defaults to `AI`; it is used for the drawer title and the assistant's message
label. `placeholder` defaults to
`Ask AI about the docs` and is shared by the compact prompt and drawer input.
The drawer stays open while
readers navigate between documentation pages and does not block the rest of the
page.

Its chrome follows the selected documentation theme. For example, `grain` uses
a full-height right panel with a left border, while the other themes keep a
floating panel treatment.

## Verify the result

Run the project's typecheck and build commands after changing configuration.
They resolve each configured MDX page and report missing paths or malformed
navigation before the site is deployed.

<Callout type="info" title="Keep page metadata close to the page">
  Put a page's <code>title</code> and <code>description</code> in its MDX
  frontmatter. Keep shared site settings in <code>heyo-docs.config.ts</code>.
</Callout>
