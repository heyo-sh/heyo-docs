# Tables

Use a table when readers need to compare the same attributes across a small
number of options. Tables are strongest when every cell is short and each row
can be understood without a paragraph of surrounding prose.

## Compare like with like

For example, a configuration reference can show the setting, its purpose, and
a representative value.

| Setting   | Purpose                                | Example                      |
| --------- | -------------------------------------- | ---------------------------- |
| `content` | Directory containing MDX source files. | `"content"`                  |
| `theme`   | Built-in documentation theme.          | `"grain"`                    |
| `mode`    | Initial color preference.              | `"system"`                   |
| `siteUrl` | Canonical public site origin.          | `"https://docs.example.com"` |

## Keep cells concise

Move long explanations, procedures, and code samples out of the table. Link to
a focused guide instead of stretching a table past the point where it can be
read horizontally.

| Use a table for        | Use a section for      |
| ---------------------- | ---------------------- |
| Compact comparisons    | A multi-step procedure |
| Option defaults        | A detailed explanation |
| Short reference values | A large code example   |

If a reader must act on the information in a specific order, use a numbered
list or [Quickstart](/quickstart) instead.
